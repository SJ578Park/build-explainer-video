# 설명할 내용에 따른 효과 가이드

먼저 청중이 알아야 할 관계를 고른다. 효과는 그 관계를 드러내는 방법이다. 아래 지속시간·크기·색은 제작 시작값이며, 참고 영상에서 측정한 수치가 아니다. 발표장의 화면 크기와 실제 음성 길이에 맞춰 조정한다.

## 선택표

| 전달할 내용 | 효과 ID / 화면 구성 | 설명에 도움이 되는 동작 | 정지 화면으로 쓸 때 | 피할 사용 |
|---|---|---|---|---|
| 한 문장 정의·핵심 주장 | `keyword-reveal` / 큰 핵심어와 짧은 보조 문장 | 말하는 단어가 등장하고 핵심어만 색을 바꿈 | 문장 전체가 완성된 뒤 유지 | 모든 단어를 튀게 해서 읽기를 방해 |
| 개념의 구성요소 | `card-focus` / 같은 크기 카드 2–4개 | 현재 항목의 테두리·명도 강조를 순서대로 이동 | 모두 읽을 수 있는 최종 상태 | 비활성 카드가 너무 흐려 비교 불가 |
| 방식·대안 비교 | `aligned-compare` / 같은 행과 기준으로 정렬 | 한 기준씩 양쪽을 함께 공개 | 판단 기준·장단점·조건을 함께 남김 | 한쪽만 유리한 축·면적·색으로 표현 |
| 입력→결과·개선 전후 | `before-after` / 같은 구도 좌우 비교 또는 분할선 | 입력을 먼저 보여준 뒤 결과 등장, 필요하면 경계 이동 | 전·후 라벨과 달라진 지점 고정 | 서로 다른 조건의 결과를 같은 실험처럼 제시 |
| 일의 순서·작동 방식 | `flow-trace` / 노드와 연결선 | 노드→연결선→다음 노드 순으로 진행 | 전체 흐름과 현재 단계가 남음 | 관계 없는 장식 화살표, 상관관계를 인과로 표시 |
| 원인·병목·재작업 | `bottleneck` / 흐름 일부에 대기·역행 표시 | 한 단계의 병목을 확대하고 전체 흐름으로 복귀 | 문제 단계·영향·검증할 가설 남김 | 근거 없이 특정 사람을 원인으로 단정 |
| 비율·규모·절감 | `quantity-fill` / 막대·용기·비율 도식 | 기준량을 먼저 만든 뒤 채움·구간 강조, 마지막에 수치 고정 | 기준·단위·수치·기간을 읽을 수 있게 유지 | 30%와 30%p 혼동, 축 생략으로 크기 과장 |
| 역사·발전·기간 비교 | `timeline` / 정렬된 시간축과 사건 마커 | 구간을 그린 뒤 사건·종료·계속됨 표시 | 출발점·종점·주요 사건 표시 | 축을 생략한 길이를 정량 비교처럼 사용 |
| 시스템·이해관계자·소유 관계 | `relationship-map` / 군집·경계·노드 | 영역을 먼저 나누고 관계를 순차 공개 | 범례·역할·관계의 뜻 유지 | 복잡한 노드를 한 번에 등장 |
| 근거·인용·실제 문서 | `evidence-callout` / 문서·자료 카드와 인용 범위 | 출처 맥락→관련 부분 확대→짧은 하이라이트 | 날짜·출처와 해당 문장 남김 | 문맥을 자르거나 생성 자료를 실제 문서로 위장 |
| 도구 조작·실제 결과 | `screen-focus` / 실제 화면과 확대 영역 | 위치를 보여주고 대상 강조→조작→결과 확인 | 작업 결과가 안정된 상태 | 로딩·개인정보·작동 실패를 성공처럼 편집 |
| 실제 사례·감각적 맥락 | `context-cutaway` / 전체 화면 사진·영상 | 설명 개념을 실제 장면으로 연결한 후 도식으로 복귀 | 움직이는 얼굴보다 별도 요약 프레임 권장 | 출처 불명 B-roll을 사건 증거처럼 사용 |
| 추상 개념의 비유 | `visual-metaphor` / 사물과 개념의 대응 | 사물을 먼저 제시하고 대응 관계를 짧게 표시 | 무엇을 비유한 것인지 명시 | 비유로 사실·수치를 증명하려 함 |
| 생각의 수정·문제 재정의 | `reframe` / 기존 문장→분해→다시 조립 | 대상·상황·행동·장애·결과를 색/위치로 대응 | 최종 정의와 바꾼 근거 유지 | 문장만 바꾸고 근거가 생긴 것처럼 표현 |
| 사례 묶기·회고·결론 | `recap-build` / 고정된 카드 자리 | 사례별 카드가 채워지고 공통 원리 연결 | 완성 카드와 공통 결론 유지 | 내용이 차기 전에 Break를 둠 |
| 청중 질문·실습 진입 | `question-hold` / 질문 하나와 필요한 맥락 | 다른 동작을 정리한 뒤 질문이 나타남 | 질문과 답변에 필요한 근거를 함께 남김 | 발표자만 아는 질문, 정답을 미리 노출 |

## 효과를 장면으로 만드는 방법

### 카드와 순차 강조

그리드는 위치를 읽는 보조 배경이다. 낮은 대비로 유지하고 텍스트보다 시선을 끌지 않게 한다. 카드 내부는 `짧은 이름 → 구체적인 이미지/아이콘 → 한 줄 설명` 정도로 구성한다. 항목이 많으면 한 화면에 축소해서 넣기보다 의미 있는 묶음으로 나눈다.

등장과 강조 이동은 약 0.25–0.5초부터 시작한다. 현재 카드가 강조되어도 다른 항목의 이름은 읽혀야 한다. 설명이 끝나면 카드 전체를 읽을 수 있는 정적인 비교 상태로 정리한다. 해당 장면의 내레이션이 끝난 뒤가 Break 후보이다.

### 연결선과 인과 설명

노드가 보이기 전에 연결선이 먼저 목적지 없는 선으로 움직이지 않게 한다. 흐름의 방향과 화살표가 뜻하는 관계를 일치시킨다. 원인·가설·데이터 흐름·담당자 이동은 서로 다른 의미이므로 선 스타일이나 짧은 라벨로 구분한다.

길게 그려지는 선은 탐색 방향을 알려줄 때 유용하다. 연결 전체가 이미 잘 보이면 단순 하이라이트만 사용해도 된다. 완성 그래프에 계속 펄스를 넣으면 멈춤 화면의 핵심이 흐려진다.

### 수치·채움·시간축

수치를 크게 쓰기 전에 기준을 정의한다. 예를 들어 감소율이면 원래 값과 비교 시점을, 시간축이면 실제 연대 또는 개략 도식 여부를 명시한다. 숫자 카운트업은 최종값을 잠깐 보여주는 장식이 아니라 변화 방향을 알려줄 때 쓴다. 숫자가 움직이는 도중에는 Break를 두지 않는다.

정확한 측정값이 없는 문제정의 워크숍에서는 실제 수치를 만들어 넣지 않는다. `예시`, `가설`, `인터뷰로 확인할 항목`을 표시하거나 크기 대신 항목의 존재만 표현한다.

### 화면 캡처와 확대

전체 위치→관심 영역 확대→동작/근거→전체 맥락 복귀 순서가 유용하다. 한 화면에서 카메라 이동, 문장 등장, 커서 이동을 동시에 크게 움직이지 않는다. 확대해도 출처·메뉴 위치·결과가 사라져 오해를 만들지 않는지 본다.

영상 프레임 자체에 효과를 렌더링한다. video-slide의 YouTube 플레이어 위에 임의의 외부 효과를 얹어 구현하지 않는다. 실제 제품 캡처와 도식으로 다시 그린 개념 화면은 시각적으로 구별한다.

### 재정의 장면 예시

원고: `AI 챗봇을 만들자`에서 `야간 문의 고객이 답을 기다리다 신청을 포기하는지 확인하자`로 질문을 바꾼다. 이는 실제 조사 결과가 아닌 설명용 예시다.

1. 첫 문장을 보여주고 `수단`을 표시한다.
2. 대상·상황·관찰할 행동을 빈칸 카드로 펼친다.
3. 가설 문장의 각 구절을 같은 카드에 대응시킨다.
4. `어떤 증거가 있으면 이 가설을 버릴까?`를 질문으로 남긴다.
5. 배포용 내레이션은 검증 방법까지 설명하고 다음으로 이어진다. 현장 발표는 질문 화면에서 멈춰 토론할 수 있다.

## 시각 리듬과 공통 문법

같은 설명 관계에는 같은 효과를 반복해 학습 부담을 낮춘다. 정의 카드, 실제 사례, 흐름도 사이의 전환은 논리 변화와 맞춘다. 몇 초마다 효과를 바꾸는 기계적인 규칙은 사용하지 않는다.

처음에는 밝은 설명 배경, 어두운 강조 배경, 전체 화면 자료라는 세 가지 무대를 선택적으로 사용하면 충분하다. 색이 위험/선택/결과 같은 의미를 갖는다면 전 장면에서 유지한다. 화면의 큰 글자는 기억할 핵심을 맡는다. 대사 자막은 영상에 번인하지 않고 배포용 선택형 트랙으로 분리하며 발표 시에는 표시하지 않는다.

줌·패럴랙스·휘프·글리치·빛 번짐·3D는 필요할 때 추가하는 연출이다. 이번 관찰만으로 채널의 상시 효과라고 확정하지 않는다. 특히 전환 효과로 장면 내용과 근거를 가리거나 Break 주변을 불안정하게 만들지 않는다.
