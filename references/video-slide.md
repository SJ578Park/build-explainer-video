# video-slide로 같은 영상을 발표에 사용하기

서비스: https://video--slide.web.app/

소스: https://github.com/SJ578Park/videoslide

확인일: 2026-09-17, 소스 main `e6d12692caf126c7331d174d3d4a26506586fc8e`.

## 확인된 계약

video-slide는 YouTube IFrame 플레이어를 구간별로 재생하고 Break에서 멈추는 발표 도구다. 시각 효과는 업로드 영상 자체에 담는다. 현재 `VideoSource.provider`는 `youtube`이며 로컬 MP4·임의 HTML 장면·JSON 계획 파일을 영상 대신 넣는 기능은 확인되지 않았다.

수동 Break와 로컬 프로젝트는 로그인 없이 사용할 수 있다. `지금 Break` 또는 B로 재생 중 마킹, 드래그·0.1초 입력·삭제/병합으로 조정한다. 인접 경계와 최소 0.5초 간격을 둔다. Space/다음 구간 재생으로 계속하고 F로 영상 영역을 전체화면으로 전환한다. 실제 단축키는 입력창에 초점이 있을 때 동작하지 않는다.

Google 로그인은 클라우드 저장·공개 링크·선택적 AI 제안에 필요하다. 공개 스냅샷·포크·iframe에는 비공개 발표자 메모가 포함되지 않는 구조다. 프로젝트 코드에 권한과 공개 스냅샷 규칙이 있으며, 새 공개본을 만드는 작업은 해당 프로젝트 배포 범위에 따라 수행한다.

2026-09-17 배포된 Mochi 가이드에서 4.0초 자동 정지, 다음 구간 재생 후 8.0초 자동 정지를 확인했다. 임의 영상 전체, 모든 브라우저, 로그인·게시 과정, 현장 네트워크를 검증한 것은 아니다.

## 같은 마스터를 설계하는 방식

예를 들어 30fps에서:

| 요소 | 프레임 | 시간 |
|---|---:|---:|
| 설명 음성이 끝남 | 825 | 27.5초 |
| 요약 화면이 안정됨 | 840 | 28.0초 |
| video-slide Break | 870 | 29.0초 |
| 다음 장면 시작 | 900 | 30.0초 |

배포 시청자는 2초의 자연스러운 요약 쉼 뒤 다음 설명으로 넘어간다. 현장 발표는 그 안의 29초에서 멈춰 필요한 만큼 토론한다. Break 전후 0.6초 여유를 두어 문장·동작 중간 정지를 피한다. 선언된 안정 구간 안에서도 플레이어 오버레이가 핵심 내용을 가리지 않는지 리허설한다.

장면 경계(여기서는 30초)와 재생 구간 경계(29초)를 구분한다. Break를 다음 장면의 첫 프레임이나 페이드 중간에 두면 제목만 바뀌거나 빈 화면에서 멈출 수 있다. 정지 때 보일 질문·도식·완성 문장 자체를 영상에 렌더한다. 장시간 대기·사회자의 현장 멘트는 영상에 삽입하지 않고 메모에 둔다.

영상 끝은 별도 중간 Break로 입력하지 않는다. 마지막 구간은 실제 종료까지 재생한다. 마지막 프레임에 정지용 추가 시간을 원하면 최종 렌더에 포함시킨다.

## 발표자 메모와 경계의 주의점

현재 소스의 `findSegmentIndex`는 `startSec <= time < endSec`이다. 정확히 29초에서 멈추면 플레이어의 활성 구간은 **29초에서 시작하는 다음 구간**이다. 편집기의 선택 카드/메모와 현재 재생 구간이 항상 같다고 가정하지 않는다. 전체화면 프롬프터의 표시도 실제 브라우저로 확인한다.

따라서 정지 때 필요한 메모는 다음 구간 메모의 첫 부분에 `시작 정지점에서 할 말`로 배치한다. 그 뒤에 `재개 후 설명`을 둔다. 수동 편집 중에는 직전 구간의 끝 Break를 선택해 시간을 바꾼다. 시간 조정 대상과 메모 입력 대상이 다를 수 있다.

이 스킬의 내보내기는 해당 매핑을 `presenter-notes.private.md`에 표시한다. 공개 입력표에는 시간·구간 제목·정지 화면만 넣고 메모를 넣지 않는다. 메모에서 청중에게 꼭 전달해야 할 개념이 발견되면 대본에도 반영한다.

## 서비스 입력과 리허설

1. 최종 영상 파일과 버전을 고정한다. 사용자가 지정한 계정·공개 범위로 YouTube에 올리거나 업로드된 최종 URL을 사용한다. 이 스킬 자체는 업로드 권한을 새로 부여하지 않는다.
2. 서비스에서 URL을 연결해 프로젝트를 만든다. 실제 영상 ID와 길이를 계획과 비교한다. 다른 버전의 YouTube 영상에 이전 Break를 적용하지 않는다.
3. `manual-breaks.md`의 구간 제목과 초 단위 Break를 수동 입력한다. AI 제안은 선택이며 검토된 시간표가 있으면 필수 단계가 아니다.
4. 비공개 메모를 지정 구간에 넣고 리허설한다. 각 정지 화면, 다음 구간 재생, 앞뒤 이동, 전체화면, 소리 설정, 메모 프롬프터를 확인한다.
5. 연속 배포용 YouTube 링크와 정지 기능이 있는 video-slide 링크를 구분해 안내한다. 공개 링크에 발표자 메모가 노출되지 않는지 확인한다.

현재 UI/코드에서 확인한 JSON 가져오기 엔드포인트는 없다. `public-breaks.json`은 수동 입력·미래 어댑터용 자료이며 현재 서비스가 직접 읽는 파일이 아니다. UI를 거치지 않고 localStorage/Firestore에 쓰거나 내부 API를 만들어 호출하지 않는다. 서비스가 향후 가져오기를 지원하면 공개 계약과 검증 결과를 이 문서에 갱신한다.

YouTube 컨트롤·광고·브랜딩은 가리지 않는다. 원격 영상 바이트를 다운로드하거나 스크랩하지 않는다. 발표 환경의 네트워크·재생 제약이 있으면 사용자가 소유한 제작 마스터를 별도 비상 재생 자료로 준비할 수 있지만, 현재 video-slide의 MP4 재생 기능이라고 설명하지 않는다.
