# 실제 제작을 반영해 전역 스킬 개선하기

스킬은 처음부터 완성된 스타일 규칙 모음이 아니라, 실제 발표 내용과 검증 결과를 바탕으로 발전시키는 제작 가이드다. 사용자가 이 스킬의 지속 개선을 요청한 프로젝트에서는 장면을 구체화하거나 피드백을 반영하는 작업에 아래 절차를 포함한다. 별도 일정이나 백그라운드 실행을 만들지는 않는다.

## 프로젝트에 남길 것과 전역으로 옮길 것

| 프로젝트에 보관 | 전역 스킬의 개선 후보 |
|---|---|
| 행사·고객·발표 원고와 미공개 결정 | 어떤 설명 관계에 어떤 효과가 이해를 도왔는지 |
| 실제 참가자 사례와 인터뷰 | 익명화한 일반적 장면 패턴 |
| 이번 브랜드·폰트·배경·정확한 길이 | 읽기·강조·전환·정지 화면에 대한 검증된 원칙 |
| 실패한 렌더와 원본 자료 | 실패 원인과 최소한의 재현 예제 |
| 개인 발표자 메모 | 구간 경계/메모 매핑에서 확인한 서비스 계약 |

## 작은 개선 루프

1. 실제 장면이나 리허설에서 무엇이 어려웠는지 기록한다. 예: 비교 카드가 차례로 나타나서 두 항목을 동시에 비교하지 못했다.
2. 프로젝트에서 가장 작은 수정으로 해결한다. 예: 두 카드의 축을 고정하고 같은 행을 동시에 공개한다.
3. 수정된 장면을 실제로 재생·정지해 확인한다. 취향인지 이해도 문제인지, 특정 청중/화면 조건인지 표시한다.
4. 재사용할 가치가 있으면 효과 가이드의 해당 항목을 보완한다. 새 기능이면 계획 형식·예제·검증기를 함께 바꾼다.
5. 검증되지 않은 아이디어는 프로젝트의 실험 메모에 두고 전역 의무 규칙으로 승격하지 않는다.
6. 공개 배포가 작업 범위에 포함되면 원격 변경을 확인하고 작업 브랜치에서 검증·PR·릴리스를 진행한다. 다른 사람의 진행 중 변경이나 로컬 수정을 덮어쓰지 않는다.

실제 제작 결과를 전역에 반영할 때 사용자에게 어떤 재사용 규칙이 바뀌었는지 짧게 알린다. 요청된 작업 범위가 기획까지만이라면 아직 렌더되지 않은 예제를 검증 완료로 표시하지 않는다.

## 개선 기록 양식

프로젝트의 `review.md`에 필요한 항목만 기록한다.

```text
설명 목표:
관찰한 어려움:
적용한 효과와 이유:
바꾼 화면/타이밍:
검증한 범위와 결과:
이 조건에서만 적용:
전역 반영 위치 또는 보류 이유:
```

공개 저장소에는 사용자 데이터, 계정 정보, 비공개 링크, 영상 원본을 포함하지 않는다. 새 예제는 합성한 일반적인 내용으로 작성한다. 릴리스에는 사용자 입장에서 무엇을 더 잘 만들 수 있게 되었는지와 실제 검증 범위를 적는다.
